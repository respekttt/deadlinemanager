# Bun ≥ 1.3 (ESM) як єдиний runtime і toolchain

- **Date:** 2026-10-14

## Context and Problem Statement

DeadlineHub — невеликий REST API, який пишуть люди разом із ШІ. Філософія проєкту (README.md): **менше коду — менше помилок**, мінімум залежностей і конфігурації. Потрібні runtime для JavaScript, пакетний менеджер, тест-раннер і драйвер SQLite. Чи можна отримати все це без окремого набору інструментів, кожен з яких треба встановити, налаштувати й оновлювати?

## Considered Options

- Bun ≥ 1.3 (ESM)
- Node.js + npm/pnpm + окремі тест-раннер і SQLite-драйвер

## Decision Outcome

Обраний варіант: «Bun ≥ 1.3 (ESM)», бо в одному бінарнику він дає runtime, пакетний менеджер (`bun install`), тест-раннер (`bun:test`, див. ADR 0004) і вбудований SQLite-драйвер (`bun:sqlite`, див. ADR 0003). Це менше залежностей і менше конфігурації, що прямо відповідає філософії проєкту.

### Consequences

- Добре, бо одна залежність середовища замість кількох: `bun install`, `bun test`, `bun audit` — усе з одного інструмента.
- Добре, бо `bun install --frozen-lockfile` дає відтворювану збірку (C8), а `bun audit` — аудит залежностей без сторонніх утиліт (C9).
- Добре, бо `bun test --coverage` з порогом у `bunfig.toml` закриває перевірку покриття (C6) без окремих пакетів.
- Добре, бо ESM за замовчуванням — без змішування CommonJS і ESM.
- Погано, бо Bun молодший за Node.js: частина npm-пакетів може мати відмінності в поведінці, а команда й ШІ менше знайомі з його нюансами.
- Погано, бо прив'язка до Bun-специфічних модулів (`bun:sqlite`, `bun:test`) ускладнює можливу міграцію на Node.js.
